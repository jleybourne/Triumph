# Picture correctness safety net (design, nothing built or run)

Tree: D:\victory-work\wt-bisect. Existing hooks: `capture.rs` (victory-gpu) has `save`, `save_as`, `read_back`, `to_rgba`, `dump_targets`, `black`, `recent_levels`, `frame_drew`; `gpucapture.rs` handles RenderDoc/PIX; `marker.rs` names draws; `pipeline.rs` ~l.523-535 parses VICTORY_SKIP_PIPELINES; `diff_tests.rs` has `translated_shaders_draw_as_pc_ones`, `translated_mesh_shaders_draw_as_pc_ones`, `translated_compute_matches_pc`, `float_semantics_are_the_consoles`, helpers `compile`, `user_data`, `close`, `tools`.

## 1. Per-run picture checks (new: crates/victory-gpu/src/picturecheck.rs, plus tools/picture_check bin)
Run on the frames `capture.rs` already saves (VICTORY_CAPTURE_FRAMES / WORLD), after `to_rgba`, so no extra GPU readback. Emit one JSON per run: `picture_report.json`, with pass/warn/fail per frame.
- `flat_frame(rgba) -> Verdict`: luma std-dev < ~2, or >98% of pixels within 3 levels of one colour, or distinct 5-bit colours < ~16. Catches black/white/single-colour frames. Reuse `black()` / `recent_levels()` logic. Misses a plausible-looking but wrong scene.
- `histogram_band(rgba, band)`: 16-bin per-channel + luma histogram, compare to a reference band (per bin min/max over N known-good runs of the same scene, widened ~25%), plus mean luma and mean saturation. Use coarse bins and a score (sum of excess outside band), because the world animates. Reference band built by `picture_check --learn <dirs of good runs>`. Catches wrong tonemap, missing lighting pass, half-black frames, colour cast. Misses small local artefacts and a band that is too wide; needs rebuilding per scene/resolution.
- `saturated_blocks(rgba)`: divide into 8x8 tiles, flag tile when >60% pixels have HSV S>0.85, V>0.5, hue within red (or any hue as a separate counter), and the tile's neighbours are not. Report count of tiles and largest connected component; compare against reference counts (good runs have near zero except UI/blood/fixed red). Also flag blocky structure: many adjacent tiles with exactly identical colour (block-quantised garbage). Catches the red-clothing class. Misses artefacts that are not saturated (grey/black blocks, NaN-to-black), and legitimate red objects (use a band, not zero; optional ignore-mask rectangles).
- Run-level: require frame count >= N, draw count (from `frame_drew`) within band, and fps is only a log field, never a pass criterion. Wire into the existing run script with exit code.
- Dump the same checks on `VICTORY_DUMP_TARGETS` outputs for intermediate targets (flat/NaN/Inf target = early signal, e.g. G-buffer all zero while final looks ok). Needs HDR decode (already in `to_rgba`).
Effort: ~2-3 days (Rust, no deps beyond existing png writer; need a PNG decode or work in-process from `to_rgba`). Reference-band tuning is the long part (+1-2 days of real runs).

## 2. Per-shader A/B inside one frame
Feasibility: yes, in two ways; recommend the own-path one.
- A (own path, recommended): add `VICTORY_AB_SWITCH` handling at replay of a single frame. Straight option without replay: run the title twice with identical input to the same frame is NOT valid (non-determinism). So instead record the frame: new `crates/victory-gpu/src/framerec.rs` logs the command stream of one frame (the draws/dispatches already pass through one choke point used by `marker.rs`) with resource contents snapshotted at frame start. Replay it twice in-process, switch off vs on, via `dump_one`/`read_back_of` per draw (readback every draw's bound RTs, or only after draws, bounded by VICTORY_AB_DRAWS). Diff with a per-draw mean/max abs error and changed-pixel fraction, ranked by shader hash. Difficulty: snapshotting all descriptors/heaps/UAV/ReBAR memory; GPU-written buffers from earlier passes must be restored. Effort: 2-3 weeks, risky with the memory-model switches since the capture must be taken under the same model.
- B (RenderDoc): take two .rdc (`VICTORY_CAPTURE_TOOL=renderdoc`, `VICTORY_CAPTURE_AT`) with switch off/on and diff with the RenderDoc Python replay API (`renderdoc` module: `SetFrameEvent`, `GetTextureData`, `GetPipelineState().GetOutputTargets`). Because the captured frames differ in content, per-event diffs are only meaningful where draws match by marker name/shader hash and the inputs are the same; works when frames are near-identical (title/menu, paused scene), poorly in the animated world. Cheaper alternative with RenderDoc: replay ONE capture and use the API to swap a shader (`ReplayController.ReplaceResource`) with the other translation, then diff per event: true same-input A/B. This needs both translations exposed as DXIL blobs (add `VICTORY_DUMP_SHADERS=<dir>` writing old/new DXIL by hash) and the replaced shader has the same signature. Effort: script ~3-4 days (tools/rdc_ab.py), plus dump option ~1 day. Catches: any shader whose output changed on real inputs, including resource/binding-dependent bugs. Misses: effects of memory model/wave64 switches that change the capture itself (the capture has the resulting data baked in); non-shader switches (needs path A).
- Pixel pitfall: diffs of draws with blending/depth need the same pre-state; RenderDoc replay gives this for free, own-path needs the snapshot.

## 3. Bisect a visual artefact to a shader (procedure, mostly doc + small tooling)
1. Reproduce and take a frame: `VICTORY_CAPTURE=<dir> VICTORY_CAPTURE_FRAMES=<n>` to confirm the artefact is present; run `picture_check` to give a number (saturated tile count).
2. Capture the GPU frame: `VICTORY_MARKERS=1 VICTORY_CAPTURE_TOOL=renderdoc VICTORY_CAPTURE_AT=<n>`. In RenderDoc open the Event Browser (names show shader hashes), step to the final image, use Pixel History on one bad pixel: the last draw that wrote it is the suspect; note its hash. Check intermediate RTs with the texture viewer to see whether garbage is already in the G-buffer.
3. Confirm by elimination: rerun with `VICTORY_SKIP_PIPELINES=<hash>` (16 hex digits, comma list). Artefact region disappears or turns to background = this shader writes it. If several candidates, binary-search the list (halve the hash set each run); use `picture_check` count as the oracle so it is scriptable: tools/bisect_skip.ps1 (new, ~1 day) taking candidate hashes from the RenderDoc event list or from a `VICTORY_MARKERS` log.
4. Confirm the translation: dump the shader (the `VICTORY_DUMP_SHADERS` above), inspect DXIL/HLSL; build a diff test (item 4) with that shader's inputs from the capture (constants via RenderDoc constant buffer view).
5. Cross-check with switches: toggle each experimental switch with only that shader's output compared (RenderDoc replay replace, item 2B) to decide whether the shader or the memory model is at fault.
Caveat: skipping a draw also changes later passes (e.g. SSAO reading it); compare locally in the artefact region, not the whole frame. Pixel history needs a non-compressed capture on the same GPU.
Effort: procedure is free; scripting ~1 day.

## 4. Translator-level check (extend diff_tests.rs)
- New test `changed_shaders_old_new_agree` in `diff_tests.rs` (or `translate_ab.rs` next to it): for each shader in a corpus (dir of console shader binaries, list from a corpus manifest; changed set = hashes whose translation output differs between git `HEAD~` translator build and the working one, obtained by `translate_all --emit-hash <dir>` run in CI on both revisions), compile both translations with `compile`, run each as compute (or as a draw into a tiny RT as `translated_shaders_draw_as_pc_ones` does) with the same random inputs (seeded, `user_data` fills the user data, random textures/constants/buffers from reflection), and compare outputs with `close` (ULP tolerance; separate handling for NaN/denorm per `float_semantics_are_the_consoles`). Random inputs should be biased: include 0, 1, negatives, denorms, INF/NaN, integer extremes, packed-half values.
- Needs: old translator available (keep as a git worktree or a vendored `emit_prev` feature flag; simplest: the CI runs the test twice and stores outputs, then a third step diffs, avoiding two translators in one binary). Corpus: dump shaders from real runs (`VICTORY_DUMP_SHADERS`).
- Catches: translation regressions on data-independent logic, instruction-level bugs (a swizzle, half-float conversion, sample-LOD, bitfield ops), including the class that yields "blocky red". Misses: bugs in resource binding/descriptor layout, memory-model/wave64 behaviours that depend on lane layout and real buffers, shaders whose inputs must be structured (vertex data, constants with invariants; random inputs produce NaN everywhere), and cases where old and new are both wrong (only says changed vs unchanged; compare to a PC DXC compile where one exists, as the existing tests do). Subgroup ops need a real wave64 context: run with fixed workgroup size and random per-lane values to exercise it.
- Needs GPU and DXC in CI (`tools()` already skips when missing; make it a failure on the CI machine).
Effort: harness 1 week; corpus + tolerance tuning another week.

## Recommended order
(1) picture checks + gating in scripts (3-5 days) -> (3) procedure plus bisect script and `VICTORY_DUMP_SHADERS` -> (2B) RenderDoc replace-shader A/B -> (4). Skip 2A unless 2B proves insufficient.
