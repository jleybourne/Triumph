# Unattended measurement harness (design)

Read-only design; nothing here has been run. Rules from CLAUDE.md are enforced by code:
one instance only, nothing compiling, diagnostics build only, report fps/ms/draws/dropped
together, one switch per measurement, the title is never named.

## 1. Files to create

Code (repo, next to the existing scripts) `wtv-main\scripts\measure\harness\`:

| file | role |
|---|---|
| `runq.ps1` | the runner: loops over the queue, one experiment at a time |
| `lib-guard.ps1` | preflight and in-run guard (processes, stale log, disk) |
| `lib-settings.ps1` | settings.xml backup / apply edits / restore |
| `lib-build.ps1` | build step (cargo) and staging of the exe |
| `lib-shots.ps1` | screenshot loop (wraps `winshot.ps1`) |
| `lib-crash.ps1` | exit code, crashes.log delta, dump detection |
| `shotcheck.py` | black-frame / garbage detector (luminance + pHash) |
| `report.py` | runs.md rows, per-experiment result.json, summary.md |
| `queue-add.ps1` | agents' only way to enqueue (atomic, validates) |
| `queue-lint.py` | schema check of a job file (also run by queue-add) |
| `frames.py` | changed, see section 5 |

Data (not in git) `D:\victory-work\queue\`:

```
inbox\      job files dropped by agents: <priority>-<utc stamp>-<agent>-<slug>.toml
running\    the one job being run (moved here by the runner; also holds runner.lock)
done\       finished job + its results dir name appended
failed\     jobs that could not start (bad schema, build failed)
runs\<jobid>\   log, log.err, shots\, settings.before.xml, result.json, row.md
refs\       reference captures for pHash (one png per scene tag)
summary-<date>.md   written at the end of a queue drain
```

## 2. Job file (TOML, one experiment per file; a `[[run]]` array allows a chained batch)

```toml
id        = "asyncpresent-alt-001"      # unique; runner refuses duplicates in done\
agent     = "agentA"
priority  = 50                           # lower first; ties by file name
reason    = "does ASYNC_PRESENT help, A/B in one run"
base      = "confirmed"                  # named env set in env-sets.toml (parsed from run_play.ps1)
seconds   = 480
warmup_s  = 240                          # samples before this are dropped (world load)
scene     = "start-room"                 # selects pHash reference
roam      = false

[build]                                  # optional
repo   = "D:\\victory-work\\worktrees\\pipeline-samplers"
cmd    = "cargo build --profile diag --features diagnostics -p victory --target-dir target/vd3"
exe    = "target/vd3/diag/victory.exe"   # staged to the target\diag\victory.exe path
expect_rev = "d1e1af34"                  # git rev-parse HEAD must match, else failed\

[env]                                    # on top of base; one switch per job unless the job says "bundle"
VICTORY_ASYNC_PRESENT = "alt"            # "alt" => the runner expects flip lines (section 5)

[settings]                               # edits to settings.xml: xpath -> value
"//fsrQuality" = "3"

[compare]                                # optional: pair with a control run, same job
control = { env = { VICTORY_ASYNC_PRESENT = "0" } }   # run second, reported as a delta
```

`queue-lint.py` rejects: unknown env keys (checked against a list generated by grepping
`VICTORY_` in the crates), `[env]` with >1 differing key vs base and no `bundle = true`,
`seconds < 600` unless `short = true` (CLAUDE.md: 300 s never reaches steady state; the 480 s
the user uses needs `warmup_s`), missing `reason`.

## 3. Runner flow (`runq.ps1`)

1. Take `runner.lock` (a file opened with FileShare.None and holding the PID; stale if PID dead).
   A second `runq.ps1` exits at once. Only the runner moves files out of `inbox\`.
2. Pick the lowest job in `inbox\`, move it atomically to `running\` (Move-Item on the same volume).
3. Build step if present (see guard: builds run BEFORE the measured window only; after
   the build finishes, wait for `rustc|cargo|link|cl|ninja|sccache` to be gone, then 15 s idle).
4. Preflight guard (section 4). Failure to get a clean machine within 10 min -> job goes back
   to `inbox\` with `retries+=1` (max 3), then `failed\`.
5. Backup settings.xml (section 6), apply edits.
6. Clear VICTORY_* from the environment, apply base + job env. Record the resolved env into result.json.
7. Launch `run-title.ps1 -Diag -NoMove -Seconds <n>` (wraps the existing launcher; if the launcher
   is a `run_*.ps1` use it with `-Seconds` instead). Start the guard thread and shot loop (jobs of
   the runner, not of the title). Record the log pair names (new timestamp check: log mtime must be
   > launch time, killing the stale-log failure mode).
8. After exit: crash check, restore settings.xml (in `finally`), guard verdict, shots check,
   `frames.py --json --check-cpu --alt`, `report.py`.
9. Move job to `done\`, sleep 20 s (let the GPU/driver settle, ports free), next job.
10. Queue empty: write `summary-<date>.md` and stop.

Everything after step 5 sits in try/finally so settings.xml is always restored, and a
`runq.ps1 -Recover` start does the restore from `running\...\settings.before.xml` if the previous
runner died mid-run (restore marker file `restore.pending`).

## 4. Guard

Preflight (refuse to start):
- `Get-Process victory,rustc,cargo,link,cl,ninja,sccache,cargo-*` any present -> wait/retry; victory present: also
  report PID/start time. Also check `hermes_cli.main gateway run` command line (CIM) and warn if present,
  since it respawns builds (CLAUDE.md); the job proceeds only if its scheduled build task is not due
  (cannot be known) so: runner pauses the gateway-owned builds by refusing and marking `invalid:gateway` if
  any compiler appears during the run.
- GPU idle: `nvidia-smi --query-gpu=utilization.gpu,memory.used` < 5 % and < 1.5 GB; not another process in
  the compute list.
- Disk free on D: > 20 GB (logs, shots).

In-run (poll every 2 s from a background runspace, append to `guard.log`):
- any compiler process, or a second `victory.exe` (not ours by PID), or the game exit before `seconds`
  -> set `invalid_reasons += "compiler:<name>@t"`. Do NOT kill the run (CLAUDE.md rule) - it keeps going, is
  marked INVALID, and the row says so. Optionally `-AbortOnInvalid` ends it early to save the night.
- CPU load of everything except the title > 15 % over 10 s -> `noisy@t` (a warning, not invalid).
- After the run `frames.py --check-cpu` ratio < 0.6 -> invalid `starved`.
- Log mtime older than launch time, or log empty -> invalid `stale-log`.

## 5. frames.py changes (concrete)

Contract with the switches: every `alt` switch, at each flip, prints one tracing line

```
INFO victory_gpu::host: ALT <NAME> on  t=20.01
INFO victory_gpu::host: ALT <NAME> off t=40.02
```

(`<NAME>` = switch name without `VICTORY_`; one shared helper `alt_flip(name, on)` in the host crate
emits it; the first line is printed when the alt begins, so the initial phase is known. If existing
switches print a different line, either change the helper or add a regex per switch in `ALT_RES`.)

Frame lines have no timestamp, so assign phase by **file order**: the phase state is whatever the last
ALT line said.

Edit list:

```python
ALT = re.compile(r"ALT (\w+) (on|off)\b(?:\s+t=([0-9.]+))?")

# new args
ap.add_argument("--alt", nargs="?", const="auto", help="split by ALT lines (NAME or auto)")
ap.add_argument("--settle", type=int, default=2, help="frame lines dropped after each flip")
ap.add_argument("--warmup-lines", type=int, default=0)   # or --after-first-world (below)
ap.add_argument("--json", action="store_true")
```

Parsing loop (replace the `frames.append` branch):

```python
phase = None; cycle = -1; since_flip = 10**9; names = set()
for line in f:
    line = ANSI.sub("", line)
    am = ALT.search(line)
    if am:
        names.add(am[1]); 
        if a.alt in ("auto", None) or a.alt == am[1]:
            new = am[2]
            if new == "on": cycle += 1       # a cycle starts at each 'on'
            phase = new; since_flip = 0
        continue
    m = FRAME.search(line)
    if m:
        since_flip += 1
        ...draws filter as now...
        if draws >= a.min_draws:
            frames.append((ms, fps, draws, dropped, phase, cycle, since_flip))
```

Notes: if several different alt switches run in one job, require `--alt NAME` (error listing `names`).
Frames before the first ALT line have `phase=None` and are only counted in the overall stats.
Drop from the phase stats the frames with `since_flip <= a.settle` (the interval that straddles
the flip is mixed). Use `min_draws` as now, so loading is excluded; additionally every phase reports
its own draws so "fewer draws" is visible.

Output when `--alt` given:

```python
def stats(rows):  # rows already filtered
    rows.sort(); med = rows[(len(rows)-1)//2]; ...
for ph in ("on","off"):
    rs = [r for r in frames if r[4]==ph and r[6] > a.settle]
    print per-phase: samples, median fps/ms, best, mean draws, mean dropped
# paired per-cycle ratio: robust against slow drift (world streaming, thermals)
pairs = []
for c in sorted({r[5] for r in frames if r[5] >= 0}):
    on = [r[0] for r in frames if r[5]==c and r[4]=="on"  and r[6]>a.settle]
    off= [r[0] for r in frames if r[5]==c and r[4]=="off" and r[6]>a.settle]
    if len(on)>=2 and len(off)>=2: pairs.append(median(on)/median(off))
print(f"on/off ms ratio: median {median(pairs):.3f} over {len(pairs)} cycles "
      f"(min {min(pairs):.3f} max {max(pairs):.3f})")
verdict: "inconclusive" if len(pairs)<3 or (max-min) > 0.07*2 ... else "faster"/"slower"/"neutral" (|ratio-1|<0.03)
also warn if mean draws differ >5 % between phases ("a win that draws fewer draws is not a win")
```

An off-phase of one cycle pairs with the on-phase before it; the last, truncated phase is dropped
(`--drop-last-phase`, default on). `--json` prints one object: `{samples, median, best, mean_draws,
mean_dropped, cpu_ratio, starved, phases:{on:{...},off:{...}}, pair_ratio, pairs, verdict, alt_names}`
and exits 0/1/2 (2 = starved, 1 = no frames). Non-alt behaviour stays as is, byte for byte (default
without `--alt` prints the current table). Also keep `--warmup-lines` out: the draws filter already
drops loading; `warmup_s` from the job is applied by `report.py` only for the row text, not by the parser.

## 6. settings.xml backup/restore (`lib-settings.ps1`)

- Locate the file once (data dir `$env:VICTORY_DATA_DIR` or `%LOCALAPPDATA%\victory\data`, found by
  Get-ChildItem like the launcher does for crashes.log); store the path in `queue\config.json`.
- Before each run: copy to `runs\<id>\settings.before.xml`, SHA-256 to `settings.before.sha`, write
  `restore.pending` marker. Apply `[settings]` edits via `[xml]` XPath, save, copy to
  `settings.applied.xml`.
- After exit (always, `finally`): wait until the process is gone, save the file the title rewrote to
  `settings.after.xml`, copy the backup back over it, verify hash, delete marker. Warn in the row if
  the after-file differs in anything but the edited keys (the title changed something by itself).
- A **per-run known-good** copy is always restored, not the previous run's rewritten file, so no
  drift builds up over the night.

## 7. Screenshots and garbage detection

`lib-shots.ps1`: every `shot_every_s` (default 30) call `winshot.ps1` (window of the title's PID) into
`shots\t<sec>.png`; skip if the window is minimised. Also one shot at +5 s after the first world frame
(first log line with draws >= min_draws) tagged `world`.

`shotcheck.py` (Pillow + numpy; pHash by 64-bit DCT, no extra deps beyond scipy-free numpy DCT):
- mean luminance (Rec.709) of the image after cropping the title-bar; `black` if < 8/255 and the std < 3.
- `flat` if std < 2 at any brightness (solid colour), `blown` if mean > 245.
- garbage: pHash Hamming distance to `refs\<scene>.png` > 22/64 for the `world` shot AND > 22 for
  at least 3 consecutive shots -> `garbage` (a single menu/loading frame is fine). The hash is also
  compared to the previous shot: distance 0 for 5 shots in a row -> `frozen`.
- Output `shots.json`: per shot `{t, mean, std, phash, dist_ref, flags}` plus overall `picture_ok`.
- Frame-line fps with `picture_ok=false` is reported with a PICTURE FAIL flag (CLAUDE.md: 7 fps with a
  black picture is not a result). The reference capture is created once by `shotcheck.py --make-ref
  <scene>` from a human-approved shot.

## 8. Crash detection (`lib-crash.ps1`)

- Process exit code recorded (hex). Expected: killed by us at `seconds` (the launcher's
  Stop-Process -> exit 1 on kill) is **ok**; the runner stops the title itself and logs `stopped_by=runner`.
  Any exit before `seconds - 5` is `exit-early`; a code in {0xC0000005, 0x80000003, 0xC0000409, ...} or
  not 0/1 -> `crash:0x...`.
- crashes.log: record size/last-write before the run; after, take the appended bytes into
  `runs\<id>\crashes.delta.log`; any new bytes -> `crash`. Also scan `log.err` tail for
  `unhandled exception`, `panicked at`, `DEVICE_REMOVED`, `DRED`.
- The last frame line time vs launch time: if the log stops growing for 60 s while the process is alive
  -> `hang@t` (the guard polls log size).
- Result status values: `ok | invalid:<reasons> | crash | hang | no-world | picture-fail | build-failed`.
  Any status other than `ok` is written but never counted as a measurement in the delta table.

## 9. Results (`report.py`)

Per run `result.json` + `row.md`, matching the docs/runs.md columns. Row format:

```
| 28 | 2026-11-27 | d1e1af34 | confirmed + ASYNC_PRESENT=alt, fsrQuality=3 | 132.1 ms / 7.6 fps | 4,501 | 344 | on 128.9 / off 135.0 ms, ratio 0.955 (8 cycles) | ok, shots ok | runs\asyncpresent-alt-001 |
```

The row number is the next integer found by parsing docs/runs.md; the runner never edits docs/runs.md.
It writes `queue\runs\<id>\row.md` and appends all rows of the night to `summary-<date>.md`
(section "paste into docs/runs.md" in order). A human or an agent pastes them in, so concurrent
edits of docs/runs.md cannot collide.

`summary.md`: table of experiments (id, agent, status, headline numbers, invalid reasons),
alt verdicts sorted by effect size, a list of invalid/crash runs with the first guard event time, the
total wall time, and "needs a rerun" for each `invalid:*`. Control-vs-treatment jobs get a delta with
the 7 % noise band printed next to it; a difference inside the band is labelled `within noise`.

## 10. Agents queueing without collisions

- Agents never write into `inbox\` directly; they run `queue-add.ps1 -File job.toml` which:
  1. lints (`queue-lint.py`), 2. checks for a duplicate id in inbox/running/done, 3. writes
  `inbox\.tmp-<guid>` and renames to `<prio>-<utcstamp>-<agent>-<slug>.toml` (rename is atomic on NTFS,
  and the runner ignores names starting with `.tmp-`), 4. prints the queue position and estimated start
  (sum of `seconds` + 90 s overhead per job ahead).
- Unique file names (agent + UTC ms + guid suffix) so two agents never write the same path; no shared
  file is read-modify-written (no central queue.json). The runner is the sole consumer.
- Builds: agents must not run cargo while the harness holds `runner.lock` + `measuring.flag`. The flag
  `queue\measuring.flag` exists only between launch and exit of the title; `queue-add.ps1 -CanBuild`
  prints yes/no, and a helper `wait-idle.ps1` blocks an agent's build until the flag is gone. For safety
  the harness also detects compilers (guard) and marks the run invalid, so a violation is visible, not silent.
  Better: agents queue the build as the job's `[build]` section so it runs before the measurement window.
- Each job carries `agent` and `reason`; results are returned at `done\<job>.toml` (status appended) and
  `runs\<id>\result.json`, so the owner polls `queue-status.ps1 -Id <id>` rather than the runner.
- Cancel: `queue-add.ps1 -Cancel <id>` moves the file from inbox to `failed\` (only while it is in inbox);
  a job in running\ is never killed (CLAUDE.md rule).
- Priority etiquette: 10-30 reserved for the human, 50 default, 90 for speculative; max 6 queued
  jobs per agent so one agent cannot fill the night.
- The `[env]` values are checked against a per-run allow-list; paths in `[build]` must sit under
  `D:\victory-work\worktrees\` (no running arbitrary commands from elsewhere).
